Ты senior Python desktop developer. Нужно спроектировать и реализовать Windows-приложение для быстрого перевода текста с экрана.

## 1. Главная идея

Пользователь нажимает глобальную горячую клавишу `Alt+Q`.

После этого:

1. Весь экран покрывается полупрозрачным overlay.
2. Курсор становится crosshair.
3. Пользователь зажимает ЛКМ и выделяет прямоугольную область экрана.
4. Во время выделения видна рамка выбранной области.
5. После отпускания ЛКМ overlay исчезает.
6. Программа делает screenshot выбранной области.
7. OCR извлекает из изображения текст.
8. Программа определяет, русский это или английский.
9. Английский текст переводится на русский.
10. Русский текст переводится на английский.
11. Возле выделенной области появляется небольшой popup с оригиналом и переводом.
12. Popup автоматически исчезает через несколько секунд, если пользователь с ним не взаимодействует.

Приложение должно быть максимально быстрым и незаметным в повседневном использовании.

Главный сценарий:

`Alt+Q → выделил текст → получил перевод`

# 5. Service interfaces

OCR не должен быть жёстко связан с PaddleOCR.

Создай простой интерфейс вроде:

```python
class OCRService:
    def recognize(...) -> str:
        ...
```

И реализацию:

```text
PaddleOCRService
```

То же самое для перевода:

```python
class TranslationService:
    async def translate(text, source_language, target_language):
        ...
```

Это нужно, чтобы позже я мог заменить:

- OCR engine
- translation provider

без переписывания остального приложения.

# 7. Screenshot UX

После `Alt+Q`:

- появляется fullscreen transparent overlay;
- экран слегка затемняется;
- пользователь выбирает прямоугольник;
- выбранная область должна визуально выделяться;
- координаты должны корректно работать при Windows scaling / DPI;
- на `Escape` операция отменяется;
- очень маленькая случайная область должна игнорироваться;
- после выбора overlay должен исчезать до выполнения OCR.

На первом этапе обязательно нормально поддержать основной монитор.

Если поддержка нескольких мониторов не сильно усложняет архитектуру — реализовать сразу.

Если усложняет — оформить поддержку нескольких мониторов как отдельный следующий этап.

# 8. OCR

OCR должен поддерживать:

- английский;
- русский;
- отдельные слова;
- предложения;
- несколько строк.

После OCR очищать мусор:

- лишние пробелы;
- ненужные переносы;
- повторяющиеся пробелы.

Но НЕ уничтожать структуру текста полностью.

Пример:

OCR:

```text
I   have been
working here
for two years.
```

Можно превратить в:

```text
I have been working here for two years.
```

Для больших многострочных блоков допускается сохранение переносов.

# 9. Определение языка

Нужно определить основной язык текста.

Минимум:

```text
English → translate to Russian
Russian → translate to English
```

Не нужно подключать тяжёлую ML-модель только ради language detection.

Можно использовать:

- анализ Unicode;
- долю кириллицы / латиницы;
- простую дополнительную эвристику.

Для смешанного текста определить доминирующий язык.

Пример:

```text
Use React component here
```

→ English.

```text
Открой Settings и нажми Save
```

→ Russian.

API key не хранить прямо в исходном коде.

Использовать:

- `.env`
или
- локальный config

Создать:

```text
.env.example
```

Если translation provider ещё не выбран, реализовать provider abstraction и один рабочий provider.

Не привязывать всё приложение к конкретному API.

Обработать:

- timeout;
- 401/403;
- отсутствие интернета;
- rate limit;
- пустой ответ;
- invalid API key.

# 11. Popup

Popup должен быть минималистичным.

Пример:

```text
┌──────────────────────────────────┐
│ apparently                       │
│                                  │
│ по-видимому                      │
│                                  │
│ Copy                         ☆    │
└──────────────────────────────────┘
```

Требования:

- без стандартной title bar;
- always on top;
- скруглённые края;
- компактный размер;
- оригинальный текст меньше;
- перевод визуально главнее;
- кнопка Copy;
- кнопка Save / star можно подготовить архитектурно;
- popup появляется возле выделенной области;
- popup не должен выходить за границы экрана;
- если возле выделения места нет — выбрать подходящее положение автоматически.

Popup автоматически исчезает примерно через 5 секунд.

Если пользователь навёл на popup или взаимодействует с ним — не закрывать его моментально.

# 13. Поведение при повторном вызове

Продумать ситуацию:

Пользователь сделал screenshot.

OCR ещё выполняется.

Пользователь снова нажал `Alt+Q`.

Выбери простую предсказуемую модель.

Предпочтительный вариант:

- разрешить новый screenshot;
- старый translation pipeline можно отменить или заменить новым;
- не создавать бесконечную очередь запросов.

Архитектура не должна допускать race conditions.

# 19. Edge cases

Обязательно учитывать:

### Screenshot

- Escape во время selection;
- click без drag;
- слишком маленькая область;
- выделение справа налево;
- выделение снизу вверх;
- DPI scaling 125%, 150%;
- второй монитор, если его поддержка реализована.

### OCR

- ничего не найдено;
- только символы;
- цифры;
- URL;
- несколько строк;
- punctuation;
- русский + английский;
- очень длинный текст.

### Translation

- API timeout;
- invalid API key;
- offline;
- API returns empty text;
- слишком длинный запрос;
- repeated requests.

### UI

- popup возле края экрана;
- popup возле taskbar;
- пользователь вызывает новый popup;
- несколько popup одновременно не нужны.

# 27. Acceptance criteria

MVP считается рабочим, если:

1. Я запускаю приложение.

2. Оно появляется в system tray.

3. Нажимаю:

```text
Alt+Q
```

4. Экран затемняется.

5. Выделяю мышью область с текстом.

6. Screenshot корректно создаётся.

7. OCR извлекает русский или английский текст.

8. Язык определяется автоматически.

9. EN переводится в RU.

10. RU переводится в EN.

11. Popup появляется возле выбранной области.

12. UI не зависает.

13. `Escape` отменяет screenshot.

14. Если текста нет — приложение не падает.

15. Если API недоступно — приложение не падает.

16. Повторное использование работает без перезапуска программы.

17. История может быть сохранена в SQLite.

18. Проект можно собрать в Windows executable.
